# Advanced configuration for GPO linking

## Blocking GPO inheritance

Remove linked GPO from ``HR_Users`` **OU** that restricted access to control panel for HR users.

Open **Group Policy Management** and navigate into ``Forest > Domains > <domain-name> > <domain-OU> > Users > HR_Users``.

Select the ``HR_Users`` folder and right-click the ``DisableControlPanel`` GPO and click delete then OK

<img width="1717" height="917" alt="image" src="https://github.com/user-attachments/assets/64488e10-76f6-4271-a184-28cf39390568" />

Now, link the the same GPO to the ``Users`` OU.

<img width="1718" height="920" alt="image" src="https://github.com/user-attachments/assets/68e155da-2948-488c-aa82-d6b75000ebae" />

This GPO is now applied for every user in the domain and should restrict access to control panel to everyone

To check this, run:
```
gpupdate /force
```
on the windows client or perform restart.

Now, let`s try blocking inheritance for ``IT_User`` **OU**. Since the GPO is applied to the parent **OU**, everyone except IT users should have their access restricted to the control panel.

In our ``<domain-OU>``, find ``IT_User`` OU, right-click and select block inheritance.

<img width="513" height="676" alt="image" src="https://github.com/user-attachments/assets/30e7341e-be3e-494b-ae59-c68ea32edbe6" />

Refresh GPO policies on the windows 11 client or perform restart to apply the new rules.

IT users now have access to the control panel while other groups don`t.

## Enforcing GPO

Let`s get back to DC. Sometimes, we might need general GPOs that apply to everyone in the domain no matter who you are.

However if the GPO is linked to the top of the domain, OUs which block inheritance will not apply those policies. This can be solved by enforcing the GPO which is applied to the parent OU.

Now, we want to apply the ``DisableControlPanel`` to the IT users and keep blocking inheritance.

Navigate into ``Users`` **OU**, right-click the policy and select **Enforced** and then **OK**.

Go back to the windows 11 client and login with IT user credentials. Refresh the GPO policies or perform restart.

Now the GPO is reapplied.

## Applying GPO to specific users or groups

We can select which groups should the GPO apply to. Even if the GPO is linked to the parent directory, it will only apply to selected groups or users.

Keep the ``DisableControlPanel`` linked to the ``Users`` OU. Disable *block inheritance* on the ``IT_Users`` OU.

Navigate into ``Group Policy Objects`` OU and select the GPO. In the **Security Filtering** section, select **Add...** and find the HR group and select OK.

<img width="458" height="249" alt="image" src="https://github.com/user-attachments/assets/3375366a-7443-4bf7-9ccb-932fe587312f" />

Next go to ``Delegation``, select **Advanced...** and here select ``Authenticated Users``. Disable the "Apply group policy" in *Allow* section and select OK.

<img width="365" height="446" alt="image" src="https://github.com/user-attachments/assets/09da661e-5f40-4cd2-a207-16eacdb23182" />

The ``Scope section`` should look like this:

<img width="1719" height="922" alt="image" src="https://github.com/user-attachments/assets/a1c7be20-1958-47e7-969c-6deb614c739d" />

Now, even though ``DisableControlPanel`` GPO is linked to the ``Users`` OU it will only apply to the HR group.

On windows 11 client, login with HR credentials and check which GPOs are applied.

<img width="1109" height="621" alt="image" src="https://github.com/user-attachments/assets/6e7c24d1-99a5-41f9-98a6-86fb26706079" />

Now login with IT user and check the applied GPOs. The applied GPO will be filtered out.
